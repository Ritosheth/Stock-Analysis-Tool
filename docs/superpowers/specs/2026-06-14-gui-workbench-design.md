# 股海贼王 GUI 工作台设计

## 目标

为当前的股海贼王命令行系统增加一个本地网页 GUI，让日常使用从“手动输入命令、打开 CSV”变成“直接双击启动、在浏览器里生成和查看报表”。

第一版定位为轻量工作台，不做登录、不做云端服务、不做自动交易、不重写现有复盘规则。

## 用户入口

项目根目录新增一个可双击启动文件：

```text
启动股海贼王.command
```

双击后执行：

1. 进入项目目录。
2. 启动本地 GUI 服务。
3. 自动打开浏览器访问工作台。
4. 在终端窗口保留运行日志，方便查看错误。

如果依赖缺失、端口被占用或 Futu OpenD 无法连接，页面和终端都应给出清楚提示。

## GUI 形态

采用纯 Python 本地网页工作台：

- 后端使用 Python 标准库 HTTP 服务，尽量不增加新依赖。
- 前端使用原生 HTML、CSS、JavaScript。
- 复用现有 `ghzw.pipeline` 和 `ghzw.validation`，不复制复盘逻辑。
- 默认监听 `127.0.0.1` 的本地端口，只服务本机访问。

推荐启动命令：

```bash
PYTHONPATH=src python3 -m ghzw.gui
```

## 页面结构

首页为一个工作台页面，包含三块核心区域。

### 1. 今日复盘

控件：

- 交易日期输入框，默认当天。
- 成交额 TopN 输入框，默认 30。
- Futu OpenD 地址和端口，高级设置，默认 `127.0.0.1:11111`。
- “生成复盘”按钮。

行为：

- 点击后调用现有每日复盘流水线。
- 显示运行中、成功、失败状态。
- 成功后自动加载生成的 CSV 表格。

### 2. 次日验证

控件：

- 日报文件选择框，自动列出 `outputs/daily/*-daily-review.csv`。
- 次日交易日期输入框。
- “生成验证”按钮。

行为：

- 点击后调用现有次日验证流程。
- 成功后自动加载验证 CSV 表格。
- 如果生成 0 行，提示检查次日是否为已完成交易日、AkShare 数据是否可用。

### 3. 历史报表

功能：

- 自动扫描 `outputs/daily/`。
- 分组显示每日复盘表和次日验证表。
- 点击报表后在页面中加载表格。
- 支持搜索、排序、常用字段筛选。

第一版筛选字段：

- `类型`
- `市场阶段`
- `题材层级`
- `个股地位`
- `次日计划`
- `验证结论`

## 表格体验

复盘表格默认优先显示以下字段：

- 代码
- 名称
- 类型
- 收盘价
- 涨幅
- 成交额
- 换手率
- 量比
- 所属行业
- 市场阶段
- 题材层级
- 个股地位
- 阶段
- 次日计划
- 一句话复盘

完整字段仍保留，可横向滚动查看。

表格支持：

- 全表搜索。
- 点击表头排序。
- 快速筛选。
- 显示当前行数。
- 打开 CSV 所在位置或下载 CSV。

## 错误处理

需要覆盖以下常见情况：

- Futu OpenD 未启动或连接失败。
- 未安装 `futu-api`。
- 未安装 `akshare`，导致次日验证不可用。
- 输出目录不存在，自动创建。
- CSV 文件为空，页面提示无数据。
- 任务运行中时禁用重复点击。

错误文案面向使用者，避免只展示 Python traceback。详细 traceback 可保留在终端日志中。

## 文件结构

建议新增：

```text
src/ghzw/gui.py
src/ghzw/gui_assets/
  index.html
  styles.css
  app.js
启动股海贼王.command
```

`gui.py` 负责：

- 启动本地 HTTP 服务。
- 提供 API：生成日报、生成验证、列出报表、读取报表。
- 自动打开浏览器。

前端文件负责：

- 渲染工作台。
- 调用本地 API。
- 展示状态、筛选、排序和表格。

## 测试策略

第一版测试聚焦低风险但关键的路径：

- 报表列表扫描函数。
- CSV 读取为 JSON 的函数。
- API 参数校验。
- 现有单元测试保持通过。

手工验证：

1. 双击 `启动股海贼王.command` 能打开浏览器。
2. 历史报表能加载已有 CSV。
3. 搜索、筛选、排序可用。
4. Futu OpenD 未连接时，生成复盘给出明确错误。
5. 次日验证选择已有日报后能生成或清楚提示 0 行原因。

## 非目标

第一版不做：

- 用户登录。
- 云端部署。
- 自动交易或下单。
- 新闻、公告、研报原因库。
- 复杂图表大屏。
- 打包成正式 macOS `.app`。

后续系统稳定后，可以再考虑封装为真正的桌面 App。
