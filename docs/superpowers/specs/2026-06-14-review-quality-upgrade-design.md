# 复盘质量提升设计

## 目标

提升每日复盘表的信息质量，解决当前四个问题：

1. `上涨原因` 长期为“不明”。
2. 题材归类混入“昨日首板、融资融券、深股通”等噪音标签。
3. 个股地位判断过粗，只按简单涨幅、连板和成交额分类。
4. 市场阶段缺少可解释的情绪指标支撑。

采用两阶段路线：

- 第一阶段：不联网，打通本地原因库、题材过滤归并、角色评分、市场情绪指标。
- 第二阶段：在第一阶段接口上接入公告、新闻、研报、龙虎榜、互动易等在线数据源。

## 第一阶段范围

第一阶段必须能在离线或仅依赖现有行情数据的情况下稳定运行。

### 本地原因库

新增本地 CSV 原因库目录：

```text
data/reasons/
```

支持文件：

```text
data/reasons/reasons.csv
```

字段：

```text
日期,代码,原因类型,原因摘要,来源,可信度
```

示例：

```text
2026-06-14,SZ.000001,公告,拟收购资产并复牌,公司公告,高
2026-06-14,SH.600001,题材,机器人板块集体走强,人工维护,中
```

匹配规则：

- 优先按 `日期 + 代码` 精确匹配。
- 如果当天没有匹配，则输出规则推断原因。
- 如果既无本地原因也无可解释规则，则保留“不明”。

`上涨原因` 字段输出格式：

```text
公告：拟收购资产并复牌
题材：机器人板块集体走强
疑似：人工智能主线发酵，个股首板放量
不明
```

### 规则推断原因

当本地原因库没有命中时，根据已有数据生成“疑似原因”：

- 主线题材 + 涨停：`疑似：{题材}主线发酵，个股涨停`
- 支线/轮动 + 放量：`疑似：{题材}轮动走强，个股放量`
- 创 20/60 日新高：`疑似：趋势突破，创阶段新高`
- 主力净流入明显：`疑似：资金净流入推动`
- 无明显线索：`不明`

规则推断必须标记为“疑似”，避免和真实公告、新闻混淆。

### 个股地位评分

新增角色评分逻辑，替代单纯粗分。

评分维度：

- 连板高度：连板越高分越高。
- 涨幅强度：接近涨停或涨停加分。
- 成交额排名：题材内成交额靠前加分。
- 换手率：适度活跃加分，极端异常不额外加分。
- 量比：放量加分。
- 市值：题材内大市值且成交额大，更可能是中军。
- 题材层级：主线中的强势股优先级高于支线/轮动。

输出仍使用原有字段 `个股地位`，取值保持：

```text
龙头
容量核心
中军
补涨
跟风
杂毛
```

第一阶段新增报表列：

- `角色分`
- `角色依据`

这两个字段用于解释为什么某只股票被归为龙头、容量核心、中军、补涨、跟风或杂毛。

判定原则：

- `龙头`：题材内连板高度或涨幅强度最高，且属于涨停/强势股。
- `容量核心`：题材内成交额最高，且涨幅为正、强于题材平均。
- `中军`：题材内市值较大、成交额较高，但弹性弱于龙头。
- `补涨`：同题材中涨幅强，但连板/成交额弱于龙头和容量核心。
- `跟风`：题材内上涨但强度不足。
- `杂毛`：题材弱、涨幅弱或与主线关联不清。

### 市场情绪指标

新增市场情绪结构：

```text
MarketSentiment
```

第一版指标：

- 涨停数。
- 跌停数。
- 上涨家数。
- 下跌家数。
- 上涨占比。
- 全市场平均涨幅。
- 连板最高高度。
- 连板家数。
- 成交额 Top30 平均涨幅。
- 昨日涨停今日平均表现。

其中“昨日涨停今日表现”依赖历史 K 线：

- 对每只股票的历史 K 线判断前一交易日是否涨停。
- 统计昨日涨停股在今日的平均涨幅。
- 如果历史 K 线不足，输出空值或“无数据”。

报表字段调整：

- `市场阶段` 仍保留文字结论。
- 新增 `市场情绪`，用紧凑文本表示关键指标。

示例：

```text
涨停82/跌停3/上涨68%/连板高5/昨板+2.6%
```

`市场阶段` 分类要基于 `MarketSentiment`，并保持原有取值：

```text
上升
高潮
分歧
修复
退潮
冰点
未知
```

## 第二阶段范围

第二阶段接入 Futu + 巨潮 CNINFO 真实证据源，并保持第一阶段的数据模型兼容。

预留统一接口：

```python
class ReasonProvider:
    def get_reasons(self, trade_date, codes) -> list[ReasonEvidence]:
        return []
```

候选来源：

- Futu：研报评级、晨星研究、资金流、回购、分红、拆合股、股东/内部人变动等结构化证据。
- 巨潮 CNINFO：信息披露公告、互动易问答。
- 后续可选：Choice、Wind、iFinD、TuShare Pro、AkShare 兜底。

证据统一为：

```text
日期
代码
原因类型
原因摘要
来源
可信度
链接
发布时间
```

合并规则：

1. 本地人工原因优先级最高。
2. CNINFO 公告优先于其他在线证据。
3. Futu 公司行动、研报评级、股东/内部人变动按证据类型排序。
4. CNINFO 互动易问答用于题材验证，优先级低于公告和明确公司行动。
5. 规则推断永远低于真实证据，并必须标记“疑似”。

新增运行参数：

```text
--evidence-source auto
--evidence-source local
--evidence-source futu
--evidence-source cninfo
--evidence-source none
```

含义：

- `auto`：本地原因库 + Futu + CNINFO。
- `local`：只用本地原因库和规则推断。
- `futu`：本地原因库 + Futu。
- `cninfo`：本地原因库 + CNINFO。
- `none`：只用规则推断。

在线证据源失败时不阻断日报生成，只打印警告并降级。

## 测试策略

新增测试覆盖：

- 本地原因库读取、日期代码匹配、优先级。
- 无本地原因时的疑似原因生成。
- 噪音题材过滤。
- 同义题材归并。
- 核心题材选择。
- 情绪指标计算。
- 市场阶段由情绪指标分类。
- 个股地位评分能区分龙头、容量核心、中军、补涨、跟风。
- CSV 输出包含新增字段。

## 非目标

第一阶段不做：

- 联网抓取公告、新闻、研报。
- 自动判断新闻真假。
- 自动下载或解析 PDF 公告全文。
- 自动交易。
- 大模型生成投资建议。

第一阶段输出是复盘辅助，不构成买卖建议。
